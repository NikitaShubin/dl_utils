# Скрипт [`check-py.sh`](../check-py.sh "Перейти к файлу")

Конвейер качества Python-кода любого проекта: ruff format → ruff check →
mypy по каждому файлу, затем pytest по найденным тестам и повторная волна
линта уже по ним.

Скрипт не привязан к репозиторию dl_utils: конфигурация линтеров всегда
берётся из dl_utils независимо от места запуска, поэтому основной сценарий -
проверка сторонних проектов, включая те, где dl_utils подключён подмодулем.

---

## Быстрый старт: чужой проект

```bash
cd ~/my_project && /path/to/dl_utils/check-py.sh
```

Без аргументов из любой папки, кроме корня dl_utils, скрипт проверяет саму
эту папку. Можно и не заходить внутрь - достаточно передать путь:

```bash
/path/to/dl_utils/check-py.sh ~/my_project
```

Каждая цель проверяется из собственной директории с путями относительно неё,
поэтому послабления конфига для тестов действуют на любой глубине вложенности,
mypy видит собственные импорты проекта, а pytest работает в его контексте
(его rootdir и pythonpath). Правила ruff/mypy при этом всегда берутся из
dl_utils и перекрывают любые настройки проверяемого проекта.

---

## Режимы запуска

| Запуск                      | Что проверяется                               |
| :-------------------------: | :-------------------------------------------: |
| с явными путями             | только указанные цели                         |
| без путей из чужой папки    | содержимое текущей папки                      |
| из корня dl_utils без путей | белый список (`root_files`) и тесты из tests/ |

Последний режим - внутренний и временный: белый список существует на период
внедрения строгих правил ruff и mypy; от него планируется отказаться.

Пути могут быть файлами или папками (несколько - через пробел). Тестовые
файлы (`test_*.py`, `*_test.py`) отделяются автоматически: сначала линтуется
основной код, затем гоняются тесты, затем линтуются сами тесты.

## Флаги

- `-f`, `--fix` — разрешить автофиксы: ruff format перезаписывает файлы,
  ruff check получает `--fix --unsafe-fixes`;
- `-g`, `--git-only` — проверять только закоммиченные в git файлы (удобно
  для CI); цель вне репозитория считается ошибкой.

По умолчанию действует режим отчёта: проблемы фиксируются в выводе и влияют
на код возврата, но файлы не изменяются. Неизвестные флаги завершают скрипт
с кодом 2 и краткой справкой (`--help`).

---

## Конвейер

1. шапка с версиями инструментов (дрейф версий виден сразу);
2. тройка ruff format → ruff check → mypy по каждому основному файлу;
3. pytest по найденным тестам каждой цели; если тестов нет - этап пропущен;
4. вторая волна format/check/mypy по самим тестам.

Финальный вердикт: код выхода 0 только при отсутствии проваленных этапов,
список провалов печатается в конце.

---

## Конфигурация

<!-- markdownlint-disable MD013 -->
- ruff и mypy получают явный путь к pyproject.toml из директории dl_utils,
  поэтому правила едины для любых проверяемых целей;
<!-- markdownlint-enable MD013 -->
- послабление для тестов задано паттерном `**/tests/**`, чтобы работать
  и во внешних проектах: assert и magic values разрешены в любых каталогах
  tests;
- pytest запускается «как есть»: каждый проект тестируется в собственном
  контексте - его строгость filterwarnings, его маркеры, его зависимости;
- при `-g/--git-only` список файлов берётся у git (`ls-files -c`),
  иначе - поиск по диску (`find`) с прунингом служебных каталогов:
  `.git`, `__pycache__`, `.venv`, `node_modules`, `dist`, `build`, кеши.

---

## Примеры

```bash
./check-py.sh ../other_project   # чужой проект целиком
./check-py.sh src module.py      # папка плюс отдельный файл
cd ../other_project && ./dl_utils/check-py.sh   # то же изнутри проекта
./check-py.sh -f src             # проверка с автофиксами
./check-py.sh -g .               # только закоммиченное (для CI)
./check-py.sh                    # белый список из корня dl_utils
```
