# 🐍 Проверка Python: check-py.sh

Конвейер: `pytest` с покрытием, затем `ruff format → ruff check → mypy` по
основным файлам и отдельно по тестам.

## 🚀 Примеры

```bash
# Проверить весь проект
/path/to/dl_utils/check-py.sh ~/my_project

# Проверить один файл
./check-py.sh cvat.py

# Проверить ноутбук
./check-py.sh Template.ipynb

# Включить правила проверяемого проекта
cd ~/my_project
/path/to/dl_utils/check-py.sh -p .
```

`check-py.sh` — часть набора из трёх чекеров с единым стилем вызова. Общие
цели, режимы, флаги, тесты и коды возврата описаны в
[«Общих правилах чекеров»](check-common.md); здесь — только специфика
Python-проверки.

## 🔧 Что происходит внутри

1. Запуск тестов и подсчёт покрытия через `pytest-cov`, если пакет установлен.
2. Линт основных файлов: `ruff format`, `ruff check`, `mypy`.
3. Линт тестовых файлов тем же набором.

`pytest` идёт первым: его метрики покрытия используются в подписях файлов на
этапе линта.

Вывод сжат: на каждый файл одна строка `▸ файл`, текст линтера показывается
только при ошибке. При успехе печатается итоговая строка этапа.

Ноутбуки проверяются так же, как Python-файлы. `mypy` не понимает `.ipynb`
нативно, поэтому для него используется `nbqa`. В стандартном режиме настройки
`nbqa` проверяемого проекта не применяются, в проектном — действуют нативно.

## ⚠️ Ограничения

- Для проверки ноутбуков нужен `nbqa`.
- `ruff` форматирует ноутбуки нативно, но сложные магические команды могут
  остаться без проверки.
- Если зависимости проекта не установлены, `mypy` и `pytest` упадут.
