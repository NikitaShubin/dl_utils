# Проверка Python: check-py.sh

Конвейер: `pytest` с покрытием, затем `ruff format → ruff check → mypy` по
основным файлам и отдельно по тестам.

## Режимы правил

По умолчанию `ruff` и `mypy` получают `pyproject.toml` из `dl_utils`, поэтому
правила одинаковы для всех проектов, а локальные конфиги и ignore-файлы
проверяемого проекта не действуют. Встроенные подавления (`# noqa`,
`# type: ignore`) сохраняются.

С флагом `-p`/`--project-config` инструменты запускаются из текущей папки и
сами находят конфиги проекта, включая пользовательские и глобальные. Конфиги
не копируются и не смешиваются: за запуск отвечает только один источник
правил. Запускайте чекер из корня проекта, иначе инструменты найдут не те
конфиги:

```bash
cd ~/my_project
/path/to/dl_utils/check-py.sh -p .
```

## Проверить проект

```bash
/path/to/dl_utils/check-py.sh ~/my_project
```

Без путей из чужой папки проверяется текущая папка; из корня `dl_utils` —
белый список `ROOT_FILES` из `checker/common.py`. Явные пути отключают белый
список.

## Проверить один файл

```bash
./check-py.sh cvat.py
```

Ноутбуки проверяются так же:

```bash
./check-py.sh Template.ipynb
```

`mypy` не понимает `.ipynb` нативно, поэтому для него используется `nbqa`.
В стандартном режиме настройки `nbqa` проверяемого проекта не применяются, в
проектном — действуют нативно.

## Флаги

- `-f`, `--fix` — `ruff format` перезаписывает файлы, `ruff check` получает
  `--fix --unsafe-fixes`.
- `-g`, `--git-only` — только закоммиченные файлы.
- `-c`, `--clean-cache` — удалить `.mypy_cache`, `.ruff_cache`,
  `.pytest_cache` в корнях целей.
- `-p`, `--project-config` — нативные правила проекта вместо `dl_utils`.
- `-q`, `--quiet-no-files` — не печатать сообщение об отсутствии файлов,
  вернуть код `3`. Используется внутри `check.sh`.
- `-H`, `--print-header` — печатать шапку с версиями инструментов и целями.

## Что происходит внутри

1. Поиск тестов `test_*.py` и `*_test.py`, запуск `pytest -q --tb=short` и
   подсчёт покрытия через `pytest-cov`, если пакет установлен.
2. Линт основных файлов: `ruff format`, `ruff check`, `mypy`.
3. Линт тестовых файлов тем же набором.

`pytest` идёт первым: его метрики покрытия используются в подписях файлов на
этапе линта.

Вывод сжат: на каждый файл одна строка `▸ файл`, текст линтера показывается
только при ошибке. При успехе печатается итоговая строка этапа.

## Тесты

Тесты принадлежат проекту и в обоих режимах запускаются по его правилам:
`dl_utils` не навязывает pytest-конфиг. Тесты ищутся по именам `test_*.py` и
`*_test.py`; нестандартный `python_files` не поддерживается. Если тестов нет,
`pytest` пропускается, а код `5` (тесты не собраны) считается пропуском.
Покрытие информационное: порог не задаётся.

## Ограничения

- В корне `dl_utils` без путей действует временный белый список; от него
  планируется отказаться.
- Проверка требует установленных `ruff`, `mypy`, `pytest` и `nbqa`. Версии
  берутся из окружения; воспроизводимость обеспечивает Docker-образ.
- `ruff` форматирует ноутбуки нативно, но сложные магические команды могут
  остаться без проверки.
