# 🧭 Как устроен dl_utils

`dl_utils` — не фреймворк и не библиотека с версиями. Это рабочий набор
инструментов, который живёт в одном git-репозитории и подключается в проекты
как подмодуль. Такой формат выбран сознательно.

## 📦 Один файл — одна единица зависимостей

Модули лежат плоско: `utils.py`, `cvat.py`, `video_utils.py` и т.д. Если модулю
нужен другой, он импортирует его по имени:

```python
from utils import mpmap
```

Корень `dl_utils` добавляется в `sys.path` (или `PYTHONPATH`), поэтому импорты
работают одинаково из любого проекта и из любого места внутри репозитория.
У модулей библиотеки нет пакетной структуры с `__init__.py`: она усложнила бы
вырезание отдельных модулей и скрыла бы реальные зависимости. Служебный
пакет `checker/` — исключение.

Практическое следствие: любой файл можно забрать вместе с его зависимостями и
использовать отдельно. Граф в [корневом README](../README.md) показывает
минимальный набор файлов для такого переноса.

## 💡 Почему не pip-пакет

- Модули сильно зависят от окружения: GPU, CUDA, версии OpenCV, TensorFlow,
  Ultralytics, CVAT SDK. Единая установка «всё сразу» тянула бы десятки
  тяжёлых пакетов даже ради одной функции.
- Репозиторий развивается вместе с основными проектами. Версионирование и
  обратная совместимость каждого модуля не являются самоцелью.
- MIT-лицензия позволяет вырезать нужный код. Подмодуль даёт один источник
  правды для всех проектов, а не набор расходящихся копий.
- Docker-образ — эталонное окружение, в котором работают все модули. Но он не
  обязателен: для лёгких модулей достаточно поставить их импорты.

## 💡 Почему нет requirements.txt

Единого списка зависимостей нет, потому что модули решают разные задачи и
тянут разные стеки. `utils.py` требует NumPy, OpenCV, PyYAML, Matplotlib,
IPython и `tqdm`; `pt_utils.py` — PyTorch; `cvat_srv.py` — CVAT SDK;
`keras_utils.py` — TensorFlow. Ставить всё сразу бессмысленно.

Зависимости модуля — это его импорты. Если нужен только `cv_utils`, ставьте
`numpy`, `opencv-python`, `matplotlib`, `IPython`, `Pillow`, `tqdm`, а также
`utils.py` с его `PyYAML`. Если нужен весь стек — используйте Docker-образ.

## 💡 Почему документация и комментарии на русском

Основные пользователи — русскоязычная команда. Идентификаторы в коде остаются
английскими: так код не конфликтует с библиотеками и остаётся привычным для
Python. Русский текст в документации и комментариях снижает порог входа для
тех, кому этот код нужен в работе.

## 📖 Как читать документацию

Страницы модулей начинаются с короткого описания и примеров. Примеры
показывают типовой сценарий, а не полный API. Дальше идут детали: устройство,
ключевые методы, ограничения. Полный список функций всегда можно посмотреть в
исходнике — docstring’и написаны для этого.

## ➕ Как добавить свой модуль

Создайте плоский файл, добавьте страницу в `docs/modules/` и обновите граф
зависимостей. Пошаговые правила, команды и устройство графа — в
[гайде по разработке](development.md).
