# Скрипт [`check-infra.sh`](../check-infra.sh "Перейти к файлу")

Линтинг инфраструктурных файлов любого проекта: docker-compose, Dockerfile,
shell-скрипты, Markdown. Конфигурация всегда берётся из dl_utils независимо
от места запуска, поэтому основной сценарий - проверка сторонних проектов,
включая те, где dl_utils подключён подмодулем.

| Категория      | Инструмент   | Конфигурация               |
| :------------: | :----------: | :------------------------: |
| docker-compose | dclint       | `.dclintrc`                |
| Dockerfile     | hadolint     | `.hadolint.yaml`           |
| shell-скрипты  | shellcheck   | авто-поиск `.shellcheckrc` |
| Markdown       | markdownlint | `.markdownlint.yaml`       |

Исключение - shellcheck: опции конфига у него нет вовсе, файл
`.shellcheckrc` ищется вверх по дереву от проверяемого файла, поэтому для
целей вне dl_utils могут применяться правила самого проекта.

---

## Быстрый старт: чужой проект

```bash
cd ~/my_project && /path/to/dl_utils/check-infra.sh
```

Без аргументов скрипт проверяет текущую папку; можно передать путь и без
cd. Каждый файл проверяется из собственной директории; неудача одного файла
не останавливает остальные.

---

## Режимы запуска

| Запуск          | Что проверяется       |
| :-------------: | :-------------------: |
| без путей       | текущая папка         |
| с явными путями | только указанные цели |

Пути могут быть файлами или папками (несколько - через пробел); файл
проверяется, только если подходит под категорию. Белых списков нет:
проверяются все релевантные файлы цели.

---

## Флаги

- `-f`, `--fix` — разрешить автофиксы там, где инструмент это умеет
  (см. таблицу ниже);
- `-g`, `--git-only` — проверять только закоммиченные в git файлы (удобно
  для CI); цель вне репозитория считается ошибкой;
- `-q`, `--quiet-no-files` — режим тишины (ставит главный `check.sh`): при
  отсутствии файлов подходящего типа ничего не печатать и выйти с кодом `3`;
  без флага выводится сообщение об отсутствии и код `0`; пустые категории
  при `-q` не выводятся вовсе;
- `-H`, `--print-header` — печатать шапку (заголовок, режим, цели); без
  флага шапка подавлена.

По умолчанию действует режим отчёта: проблемы фиксируются в выводе и влияют
на код возврата, но файлы не изменяются. Неизвестные флаги завершают скрипт
с кодом 2 и краткой справкой (`--help`).

### Возможности автофиксов

| Инструмент   | Автофикс при `-f` |
| :----------: | :---------------: |
| dclint       | да (`--fix`)      |
| markdownlint | да (`--fix`)      |
| hadolint     | нет, только отчёт |
| shellcheck   | нет, только отчёт |

---

## Конфигурация

- функции вывода и палитра цветов берутся из [`utils.sh`](../utils.sh
  "Перейти к файлу") — общего модуля скриптов dl_utils;
- конфиги линтеров (`.dclintrc`, `.hadolint.yaml`, `.markdownlint.yaml`,
  `.shellcheckrc`) всегда берутся из директории dl_utils.

---

## Дискавери файлов

<!-- markdownlint-disable MD013 -->
- при `-g/--git-only` список берётся у git (`ls-files -c`) относительно корня
  репозитория;
<!-- markdownlint-enable MD013 -->
- иначе - поиск по диску (`find`) с прунингом служебных каталогов:
  `.git`, `__pycache__`, `.venv`, `node_modules`, `dist`, `build`, кеши;
- вне git-репозитория скрипт предупреждает и проверяет всё с диска.

Финальный вердикт - суммарное число проблемных файлов, код выхода 0 только
при нуле. Если файлов подходящего типа нет вовсе: вручную (без `-q`) —
сообщение и код 0, при `-q` — код 3 (для `check.sh` и честного CI).
Одиночный файл проверяется только теми категориями, под которые подходит
(файл неверного типа молча игнорируется нерелевантными категориями).

---

## Примеры

```bash
./check-infra.sh ../other_project # чужой проект целиком
./check-infra.sh docker           # одна подпапка
./check-infra.sh -f docs          # Markdown с автофиксами
./check-infra.sh -g .             # только закоммиченное (для CI)
./check-infra.sh                  # текущая папка
```
